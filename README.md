# budget

Личное приложение для учёта финансов на Django: счета, категории, операции
(доход / расход / перевод), REST API и веб-отчёты.

## Стек

- Python 3.11, Django 5.2, Django REST Framework, django-filter
- SQLite (локальная разработка)
- Chart.js (графики), интерфейс на русском

## Структура

```
budget/                  # Django-проект
├── manage.py
├── db.sqlite3           # локальная БД
├── budget/              # настройки и корневые URL
└── finance/             # приложение
    ├── models.py        # Account, Category, CategoryKeyword, Transaction
    ├── categorization.py # подбор категории по ключевым словам
    ├── services.py      # проведение операции и изменение баланса
    ├── views.py         # REST API (/api/...)
    ├── views_pages.py   # веб-страницы (/, /incomes/, /monthly/, /balance/)
    ├── urls_pages.py    # адреса веб-страниц
    ├── templates/finance/  # base, categories, monthly, balance
    ├── importers/       # импорт выписок (Т-Банк)
    └── management/commands/
        ├── import_tbank.py
        └── recategorize.py
```

## Запуск

```bash
source .venv/bin/activate
cd budget
python manage.py migrate
python manage.py runserver
```

- http://127.0.0.1:8000/ — траты по категориям за год
- http://127.0.0.1:8000/incomes/ — доходы по категориям за год
  (пополнения, внесение наличных, кэшбэк, возвраты, зарплаты)
- http://127.0.0.1:8000/monthly/?month=2026-10 — доходы и расходы за месяц
- http://127.0.0.1:8000/balance/ — график остатка денег на счетах
- http://127.0.0.1:8000/admin/ — админка
- http://127.0.0.1:8000/api/ — REST API

### График баланса

Страница `/balance/` строит остаток по дням нарастающим итогом. Доступен
переключатель счетов: «Все счета» (плюс сводная линия) или конкретный счёт.
В таблице под графиком показаны начальный остаток, поступления, списания,
изменение за период и текущий баланс.

Начальный остаток вычисляется как «текущий баланс − сумма изменений по
операциям», поэтому последняя точка графика всегда совпадает с балансом в
админке. В остаток включены **все** операции, влияющие на деньги, включая
«неизвестные» переводы между своими счетами — именно поэтому по ним видно
крупные поступления, которые не попадают в отчёт доходов.

## Импорт выписки Т-Банка

Импорт принимает JSON, который создаёт
[`tbank-cash-flow-pdf-parser`](../tbank-cash-flow-pdf-parser).

```bash
# предпросмотр — ничего не пишет в БД
python manage.py import_tbank path/to/output.json

# запись в БД (при необходимости создаётся счёт)
python manage.py import_tbank path/to/output.json --commit
```

Опции:

- `--account "Т-Банк"` — счёт для операций (создаётся при необходимости);
- `--source tbank` — значение поля `source`;
- `--top 25` — сколько строк показывать в отчётах.

Импорт идемпотентен: повторный запуск пропускает уже загруженные операции.

### Категории и ключевые слова

Категория траты определяется по таблице **ключевых слов** в БД
(`CategoryKeyword`), а не по файлу с правилами. Слова редактируются в админке:

- **Категории → ключевые слова** — общий список;
- карточка категории — те же слова во встроенной таблице.

Для каждой строки: слово, категория, приоритет и признак «активно». При
импорте описание операции приводится к нижнему регистру, и категория
выбирается по первому совпадению в таком порядке:

1. выше `priority`;
2. длиннее совпавшее слово;
3. раньше создано.

Учитываются только слова, у которых тип категории совпадает с направлением
операции (`expense` / `income`). Неактивные слова игнорируются. Начальный
набор слов создаётся миграцией `0004_seed_category_keywords`; дальше его можно
свободно дополнять под свои мерчанты.

### Переразметка старых операций

После добавления слов уже загруженные операции сами не обновятся. Для этого
есть команда `recategorize`:

```bash
# предпросмотр: заполнит категории только там, где их нет
python manage.py recategorize --source tbank

# записать изменения
python manage.py recategorize --source tbank --commit

# полный пересчёт: меняет и уже разобранные операции,
# а категории без совпадений очищает
python manage.py recategorize --source tbank --overwrite --commit
```

Опции:

- `--account "Т-Банк"` — только операции указанного счёта;
- `--source tbank` — только операции указанного источника;
- `--overwrite` — пересчитать всё, а не только операции без категории;
- `--top 20` — сколько изменившихся описаний показывать.

По умолчанию команда не трогает операции, у которых уже есть категория, — так
ручная разметка не потеряется. Если у «неизвестной» операции находится слово,
она становится обычной операцией с категорией и перестаёт быть неизвестной.

### «Неизвестные» операции

Переводы между своими счетами без категорийного комментария сохраняются с
`is_unknown = true`: они учитываются в балансе, но не попадают в отчёты по
доходам и расходам. Внешние переводы по номеру телефона считаются расходом
категории «Прочее».
